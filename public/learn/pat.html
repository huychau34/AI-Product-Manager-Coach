AI Product Design

Copilots, assistants & agents for product managers

Choosing the wrong pattern wastes months. Copilots suggest inside a workflow; assistants answer on demand; agents take multi-step actions with tools. More autonomy means more risk, so add human-in-the-loop for high-impact steps.

There are three common patterns, ordered by autonomy. A copilot suggests inside the user's workflow and the user accepts or edits (autocomplete, draft replies). An assistant answers or performs a task when asked, usually in a chat or side panel. An agent is given a goal, plans multiple steps, uses tools such as search or APIs, and acts with less supervision.

More autonomy means more value per interaction, but also more risk. Errors compound across steps, some actions can't be undone, agents are harder to debug, and they cost more and take longer. Many problems are better solved by a fixed workflow - predefined steps that call an LLM - than by an open-ended agent.

Design principle: start with the lowest autonomy that delivers value, then earn trust. Require human approval for high-impact actions (money, deletion, messages to customers), give clear permissions, keep logs of what the AI did and why, make undo easy and failures graceful. Tell users what the AI can do and how to correct it.
