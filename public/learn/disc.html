AI Product Discovery

Finding AI opportunities & data readiness for product managers

Most AI features fail on the problem or the data, not the model. Good AI use cases: fuzzy inputs, tolerance for imperfection, plenty of relevant data, clear value if right 80-90% of the time. Check data quality, access and privacy before committing.

Start from the user problem, not the technology. AI fits where inputs are fuzzy (language, images, messy data), where a good-enough answer is still valuable, and where there are real patterns in data to learn from. Traditional rules-based software is better when the answer must be exact, fully explainable or legally binding.

Next, decide whether to automate or augment. Automate tasks that are tedious, repetitive and low-risk, with an agreed right answer. Augment - help a person do it better - when judgement, accountability or enjoyment matter. Also ask which error is worse for users: a false positive (AI acts when it shouldn't) or a false negative (AI misses something). That choice shapes the whole design.

Data readiness is usually the real gate. Do you have the data, can you access it, is it clean and representative, and are you allowed to use it (privacy, contracts, customer consent, sending it to a third-party model)? Validate cheaply before committing: run a prompt prototype on real samples, or fake it with a human behind the scenes, and measure how often the output is good enough.
